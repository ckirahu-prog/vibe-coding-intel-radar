## A · 本周跟进台

> 这周该盯哪几条？按档位分流，不是作业清单。

### 本周试一试（≤2）

- **OrbitKit**（技术 · 新出现）— 给 Godot 4（开源游戏引擎）和 Blender（3D 建模软件）用的 CLI + Skills（可复用指令包）+ MCP（让助手调用外部程序的接法）与插件管理。接下来怎么看：只接 **Godot 4** 一侧 → 按 README 装好 OrbitKit / 对应 MCP → 对空工程或现有小品 **完成一次**「助手改场景/节点并能保存或截图确认」的冒烟（≤4h）。 → [详情](#c-orbitkit)
- **game-assets-maker**（技术 · 新出现）— 本地把视频抽成可进游戏的动画帧（抠背景、对齐、裁切），可选 AI 补帧，并带 Godot 4 Skills。接下来怎么看：准备 **一段 ≤10 秒** 参考视频 → 只跑「抽帧 → 去背 → 导出一序列」→ 能在引擎或看图软件里翻帧就停（≤4h）。 → [详情](#c-game-assets-maker)

### 继续观察

- **mumblebox-foundry**（技术 · 新出现）— 本地图像/3D 资产工具箱：带引导的 ComfyUI（节点式生图工作流）+ MCP + Skill，面向游戏与 Blender。接下来怎么看：盯「Pinokio 一键装 → 助手经 MCP 出一张进引擎的图」是否有最短复现；本周试一试已满，不双开重装 Comfy。 → [详情](#c-mumblebox-foundry)
- **gdx**（技术 · 新出现）— 给 AI 助手用的 Godot 4.x 自动化 CLI：用 JSON 工作流改场景、控运行、截图、测与导出。接下来怎么看：与 OrbitKit 同属「助手进 Godot」；本周只盯它是否比 OrbitKit 更短路径完成「改一处 + 截图」，有明确更短步骤再换试。 → [详情](#c-gdx)
- **abuurka/gamestudio**（技术 · 新出现）— Blender 扩展：让助手在 Blender 里建模型/关卡与 TypeScript 玩法，浏览器用 three.js（网页 3D 库）玩。接下来怎么看：注意与上周 kumodeck/game-studio **不是同一仓库**；盯「Blender 5.2+ + 任一 MCP 客户端 → 浏览器能玩一关」第三方短证言。 → [详情](#c-abuurka-gamestudio)

### D3 可复制制作方法（≤2）

- **助手进 Godot 先冒烟再比工具**：对照 OrbitKit / gdx——最小交付是「一处可确认改动 + 截图/保存」，同周不要并跑两套 MCP/CLI。
- **视频动作先进帧再谈生成**：对照 game-assets-maker——有参考视频时先本地抽帧去背；AI 补帧放到能翻序列之后。

### D4 不建议跟（≤2，一句）

- **Reverseport（逆向/.pck/IL2CPP 再移植）**：绑定专业逆向栈与多引擎移植证明链，远超单人小品，且合规风险高。https://github.com/laaielichter/Reverseport
- **VibeApp-AI 一站式「描述→多引擎/模拟器重做」**：能力面过大（多模型、多引擎、重制任意 App），不适合当第一件 8–12 周 demo 主栈。https://github.com/CartyChris/VibeApp-AI
