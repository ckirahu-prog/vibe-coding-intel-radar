## A · 本周跟进台

> 这周该盯哪几条？按档位分流，不是作业清单。

### 本周试一试（≤2）

- **unity-MCP**（技术 · 新出现）— 把 AI 助手接到 Unity（商业游戏引擎）里：查工程、改资源、跑测试与扩展工作流。接下来怎么看：空工程或现有小品 → 按 README 装 MCP（让助手调用外部程序的接法）→ 完成一次「助手改场景/组件并能在编辑器里确认」的冒烟（≤4h）。 → [详情](#c-unity-mcp)
- **snapgrid**（技术 · 新出现）— 命令行把糊掉的像素图（放大平滑、AI 糊边、JPEG 损伤）对齐回干净像素格与统一色板。接下来怎么看：准备 **1 张**损坏/糊边精灵 → 跑 snap 导出 → 在看图软件里确认格子整齐、色板可数（≤4h）。 → [详情](#c-snapgrid)

### 继续观察

- **WASD-Engine**（技术 · 新出现）— 自称面向 AI 做游戏的开源「马具」；本周末 raw 又出现官网/HN 讨论。接下来怎么看：盯是否有「装完 → 10 分钟内出可玩切片」的第三方短证言；没有更短路径前不替换 unity-MCP 试法。 → [详情](#c-wasd-engine)
- **pixel-unslop**（技术 · 新出现）— 桌面/CLI 把 AI 像素图钉回真像素格、平色块并合并色板（离线、不再生图）。接下来怎么看：与 snapgrid 同题；本周只盯它是否对「你常用的那类糊图」更稳，有明确优势再换试。 → [详情](#c-pixel-unslop)
- **CodeForge-AI**（技术 · 新出现）— 本地优先的 AI 开发工作台，带 Godot / Unity / Unreal / Cocos / LOVE 等引擎适配。接下来怎么看：能力面过大；只盯「某一个引擎适配」是否有最短可复现步骤，不整包重装。 → [详情](#c-codeforge-ai)

### D3 可复制制作方法（≤2）

- **引擎 MCP 先冒烟再换马具**：对照 unity-MCP——最小交付是「一处可确认改动」；WASD / CodeForge 等宽口径工具有更短路径再迁。
- **糊像素先钉格再重画**：对照 snapgrid / pixel-unslop——AI 或放大糊边时，先离线对齐网格与色板，再决定要不要重生图。

### D4 不建议跟（≤2，一句）

- **ember-protocol（UE5.8 机甲 + ComfyUI→Blender→Hunyuan3D 全管线展示）**：栈过重，远超单人 8–12 周 demo。https://github.com/wuuwuu26/ember-protocol
- **noclip「可玩世界模型」当第一作**：用大模型逐帧当引擎的研究向 demo，算力与不可控性不适合当小品主栈。https://github.com/Yelar/noclip
